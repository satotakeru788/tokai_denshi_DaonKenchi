# モデル追加手順（DaonKenchi MVP）

新しい推論モデルをアプリのプルダウンに追加するための手順書です。
**追加＝S3 にモデルを置き、`manifest.json` に1行足すだけ**で、アプリの再デプロイは不要です
（Lambda は毎回 `models/manifest.json` を読み直し、フロントは起動時に取得するため）。

ただし「置けば動く」わけではありません。**モデルが本アプリの入出力契約に合っている必要があります**。
まず §1 を必ず確認してください。

---

## 0. 役割と前提

| 役割 | 作業 | 必要なもの |
|---|---|---|
| **モデル作成者(ML)** | 学習 → ONNX書き出しで `model.onnx`(+`.data`)・`meta.json` を生成（§2） | 研究repo `DaonKenti-app`、学習環境(PyTorch等)、チェックポイント `model.pt` |
| **登録担当** | 上記3ファイルをS3に置き `manifest.json` に追記（§4） | AWS書き込み権限 or 自分のsandbox、リポジトリ（任意） |

同一人物でも構いません。**AWSの権限が無い人（アプリの一般ユーザー）は画面からは追加できません**
（`models/` は全認証ユーザー read のみ）。

---

## 1. ⚠️ モデルが満たすべき契約（最重要）

推論の前処理は [`amplify/functions/infer/audio_infer.py`](../amplify/functions/infer/audio_infer.py) に固定されており、
モデルごとに変えられません。次を**すべて**満たす必要があります。

1. **形式**：ONNX（`model.onnx`、重みが外部化されていれば `model.onnx.data` も）。
   PyTorch/sklearn/TF 等なら **ONNXへ変換が必須**。
2. **入力**：**ログメルスペクトログラム** `shape = [batch, 1, n_mels, T]`（float32）。
   mel等のパラメータは `meta.json` で宣言（§3）。**生波形・MFCC・別次元を期待するモデルは不可**。
3. **出力**：**「1打あたりの非正規化 kPa」**（segmentごとにスカラー1個、`shape = [batch]`）。
   Lambda はこれを打数で平均するだけ。**出力の意味・単位が違うと結果が壊れます**。
4. **前処理**は manifest の `preprocess` でモデルごとにプロファイルを選択できる
   （省略時は既定の `logmel_v1`＝打音検出→クロップ→log-mel）。

> **独自の前処理で学習したモデル**（検出・切り出し・ノイズ除去が異なる等）は、
> 前処理コードごと持ち込めます → **[前処理プロファイル仕様.md](./前処理プロファイル仕様.md)** を参照。
> その場合の入力契約（log-mel固定）は適用されず、自分のプロファイルが出す特徴量＝モデル入力になります
> （出力契約「1打あたりkPa」は共通）。プロファイル追加はPRレビュー＋再デプロイが必要です。

## 2. `model.onnx` / `meta.json` の作り方（研究repo `DaonKenti-app`）

これらは**手書きするものではなく、学習→エクスポートの成果物**です。MVPリポジトリでは作りません。

```bash
# 研究repo DaonKenti-app 側で実行
# 1) 学習で model.pt（前処理設定・正規化統計を内包）を用意したうえで:
python tools/export_onnx.py --checkpoint <model.pt> [追加の.pt ...] --out-dir <出力先> --seed-tag <タグ>
#   -> model.onnx (+ model.onnx.data) と meta.json を生成。
#      meta.json は checkpoint の前処理から自動生成されるので、モデルと必ず一致する（手で書かない）。
#      --checkpoint を複数渡すとアンサンブルになる（exp3v2 は3シード）。

# 2) （任意）校正カーブを付ける場合 = 実測値とOOF予測から等張回帰を meta.json に注入:
python tools/export_calibration.py
#   -> meta.json["calibration"]{x,y} が入る。再学習のたびに再実行。
```

> 校正の入力に使う「実測値」は、**本アプリが `labels/` に貯めているデータ**がそのまま使えます。

出力された **`model.onnx`（+`model.onnx.data`）と `meta.json` の3点（または2点）をワンセット**で受け取ってください。
`model.onnx` と `meta.json` は不可分です（meta を手で書き換えると前処理がズレて結果が壊れます）。

## 3. `meta.json` の中身（参考）

推論で**必須**のキー（[`audio_infer.py`](../amplify/functions/infer/audio_infer.py) が読む）:

```jsonc
{
  "target_sr": 22050,        // 必須: 解析サンプリングレート
  "n_fft": 1024,             // 必須
  "hop": 256,                // 必須
  "n_mels": 96,              // 必須: 入力melの次元
  "fmin": 20.0,              // 必須
  "fmax": 3000.0,            // 必須
  "pre_seconds": 0.01,       // 必須: ピーク前の切り出し秒
  "post_seconds": 0.12,      // 必須: ピーク後の切り出し秒
  "segment_samples": 2866,   // 必須: 1打セグメント長(サンプル)
  "calibration": {           // 任意: あれば校正に使用（manifestのcalibrated=falseで無視）
    "x": [/* モデル生出力kPa */],
    "y": [/* 対応する補正後kPa */]
  },
  "seed_tag": "exp3v2-..."   // 任意: 結果に modelTag として載る
}
```

その他（`num_members` / `target_*_per_member` / `crop_mode` / `note` 等）は来歴情報で、推論には不要です。
`spectral_subtraction` は **false** 前提（Lambda移植版はSSオフ）。

## 4. 追加の手順（登録担当）

### 4-1. ローカルにモデルを置く（リポジトリを使う場合）

```
seed/models/<id>/
  ├─ model.onnx
  ├─ model.onnx.data   （あれば）
  └─ meta.json
```

### 4-2. `manifest.json` に1行足す

[`seed/models/manifest.json`](../seed/models/manifest.json) の `models` 配列に追記：

```jsonc
{
  "version": 1,
  "default": "takao16-hyb",                 // 全体の既定（後方互換のフォールバック）
  "defaults": { "16": "takao16-hyb", "15": "takao15-hyb" },  // サイズ別の代表（一般ユーザーが各サイズで使う）
  "models": [
    { "id": "takao16-hyb", "name": "16インチ hybrid_fk", "desc": "...", "path": "takao16hyb", "preprocess": "takao_v1", "tireInch": 16, "calibrated": false },
    { "id": "takao15-hyb", "name": "15インチ hybrid_fk", "desc": "...", "path": "takao15hyb", "preprocess": "takao_v1", "tireInch": 15, "calibrated": false },
    // ↓ 追加例
    { "id": "exp4", "name": "exp4（新モデル）", "desc": "2026-06版・新データ追加", "path": "exp4", "preprocess": "logmel_v1", "tireInch": 16, "calibrated": true }
  ]
}
```

| キー | 自由度 | 注意 |
|---|---|---|
| `name` | **完全に自由** | プルダウン表示名のみ。日本語OK |
| `desc` | 自由（任意） | 選択時に下に出る説明 |
| `id` | **ほぼ自由** | ① manifest内で**一意** ② **一度公開したら変えない**（`modelId`として results/labels に記録される）。英数・ハイフン推奨 |
| `path` | **自由ではない** | S3 `models/<path>/` の**実フォルダ名と一致必須**。`id`と別名でもよく、複数エントリで同じ`path`を共有可（校正あり/なしが実例） |
| `preprocess` | 登録済みプロファイル名 | 使用する前処理（省略時 `logmel_v1`）。新しい前処理の追加は [前処理プロファイル仕様.md](./前処理プロファイル仕様.md) 参照（要PR＋再デプロイ） |
| `tireInch` | `16` / `15` | このモデルの対象タイヤサイズ。**省略時は16inとみなす**。アプリのサイズ選択（16/15）でこの値が一致するモデルだけが対象になる |
| `calibrated` | bool | `false`で `meta.calibration` を無視して推論 |

### サイズ別の代表モデル（`defaults`）
アプリのユーザーは画面で **16インチ/15インチ** を選び、その**サイズの代表モデル**で推論します。代表は manifest の
`defaults["16"]` / `defaults["15"]` で決まり、**管理者(developers)が画面から個別に設定**できます
（裏で `setDefaultModel` アクションが該当サイズの `defaults[inch]` を書き換える）。
`defaults` に無いサイズは「そのサイズ先頭のモデル → 全体 `default`」の順でフォールバックします。
全体 `default`（`defaults` 無し）は後方互換用に残しています。

### 4-3. S3 に反映（3通り。相手の環境で選ぶ）

**A. リポジトリ＋CLIがある人**
```bash
python tools/seed_models.py        # = npm run seed:models（追加方式・既存は消さない）
```
※ `seed_models.py` はバケット名を `amplify_outputs.json` から読み、プロファイル `daonkenti-dev` を使います。
別プロファイルの人は B か C を使ってください。

**B. AWSマネジメントコンソールだけ（リポジトリ不要）**
1. S3 → 対象バケット → `models/` を開く
2. 新フォルダ `models/<id>/` に `model.onnx`(+`.data`)・`meta.json` をアップロード
3. `models/manifest.json` をダウンロード → 1行追記 → 上書きアップロード

**C. CLI直叩き（自分のプロファイルで）**
```bash
aws s3 cp <ローカルの seed/models/<id>> s3://<バケット名>/models/<id>/ --recursive --profile <自分のプロファイル>
# manifest.json も同様に差し替えアップロード
aws s3 cp seed/models/manifest.json s3://<バケット名>/models/manifest.json --profile <自分のプロファイル>
```

### 4-4. 反映確認
アプリをリロード → プルダウンに出れば成功（再デプロイ不要）。

## 5. ⚠️ 本採用の前に必ず検証する

入力形状が違えば 500 エラーで気づけますが、**出力の単位/意味が違う場合はエラーにならず
「それっぽい嘘の数値」**が出ます（サイレント故障）。**実測値が分かっている音で必ず検証**してください。

```bash
# デプロイ済みエンドポイントへ合成WAVを投げるスモークテスト（modelId を変えて比較）
python tools/test_endpoint.py
```
- 既知の空気圧のタイヤ音で推定し、妥当な kPa が返るか確認する。
- 校正あり/なしや、旧モデルとの値の差が説明できるかを見る。

## 6. AWSアクセスと環境の注意

- 追加先は**1つのS3バケット**。バケット名は `amplify_outputs.json` の `storage.bucket_name` で確認
  （現在のサンドボックス環境では `amplify-daonkentimvp-tksa-daonkentimvpstoragebucke-iuczqkninuaw` / `ap-northeast-1`）。
- 書き込みには **アカウント `910478837984`（ap-northeast-1）へのSSOアクセス＋バケットへの `s3:PutObject` 権限**が必要。
- `amplify_outputs.json` は **`.gitignore` 対象**。リポジトリには入らないので、登録担当に**バケット名/リージョン**（または当ファイル）を共有してください。
- **今のデプロイは個人サンドボックス（識別子 `tk_satou`）**です。別の人が自分のPCで `npx ampx sandbox` を
  実行すると**別スタック・別バケット**になり、そこに足したモデルはこの環境には出ません。
  - 「**この環境**に足す」→ 上記バケット名を使う（A/B/C）。
  - 「**自分の環境で試す**」→ クローン→`npm install`→`npx ampx sandbox`（自分のAWS）→`seed/models`に置く→seed。私のバケットへのアクセス不要。
  - 「**みんなで共用する1環境**を運用する」→ 個人sandboxではなく共有デプロイ（Amplify Hosting/パイプライン）に移行すべき（MVP後の課題）。

## 7. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `推定エラー` / 500 | `models/<path>/model.onnx.data` が無い | 現状ハンドラは `.onnx`/`.onnx.data`/`meta.json` の3点を必ずDL。外部重みなしの単一ONNXを使うなら、ハンドラの「`.data`は無ければ取得しない」改修が必要（開発担当へ） |
| 404系のエラー | `path` とS3フォルダ名の不一致、seed忘れ | `manifest.path` と `models/<path>/` を一致させ、`seed_models.py` 実行 |
| 推論は通るが値がおかしい | 出力契約（1打kPa）や `meta.json` の前処理がモデルと不一致 | §1・§3を再確認。modelとmetaは必ずセットで | 
| プルダウンに出ない | manifest未反映、JSON文法エラー | `manifest.json` の構文確認 → 再アップロード → リロード |

## 付録：校正と再学習データ

- `labels/{identityId}/{id}.json`（実測空気圧）が再学習・校正の入力になります。
- 校正カーブは研究repoの `export_calibration.py` で `meta.json` に焼き込み。
  同じ `model.onnx` に対し「校正あり/なし」を manifest の `calibrated` だけで切り替え可能です。
