# 開発者グループ運用（モデル選択UIの表示制御）

モデル選択プルダウンは **Cognito の `developers` グループ所属ユーザーにのみ表示**されます。
一般ユーザーには表示されず、`models/manifest.json` の `default` モデルで推定が動きます
（推定機能そのものは全ユーザー共通。隠れるのはUIだけです）。

仕組み：ログイン時に Cognito が発行する IDトークンの `cognito:groups` クレームを
フロント（[`src/userGroups.ts`](../src/userGroups.ts)）が読み、`developers` を含むときだけ
`<select>` を描画します。グループは [`amplify/backend.ts`](../amplify/backend.ts) が
**RoleArn なし**で作成するため、IAMロール解決（S3 / 推論URLの権限）には一切影響しません。

---

## ユーザーを developers に追加する

`USER_POOL_ID` は `amplify_outputs.json` の `auth.user_pool_id`（sandbox ごとに異なる）。

手順：①相手にアプリからサインアップ（メール認証まで）してもらう → ②次の1コマンドで追加。
`--username` には**相手のメールアドレスをそのまま**指定できる（内部UUIDに自動解決される）。

```bash
aws cognito-idp admin-add-user-to-group \
  --user-pool-id <USER_POOL_ID> \
  --username user@example.com \
  --group-name developers \
  --profile daonkenti-dev --region ap-northeast-1
```

外す場合は `admin-remove-user-from-group`（引数は同じ）。
所属確認は `admin-list-groups-for-user --user-pool-id <USER_POOL_ID> --username <メールアドレス>`。

AWSコンソールからの操作も可：Cognito → ユーザープール → グループ → developers → 「ユーザーを追加」。

---

## 注意

- **反映はIDトークンの再発行後** = 対象ユーザーは一度ログアウト → 再ログイン。
  （放置でもトークン期限切れ後の自動リフレッシュで反映されるが、最長1時間かかる。）
- グループ名 `developers` を変える場合は [`amplify/backend.ts`](../amplify/backend.ts) と
  [`src/userGroups.ts`](../src/userGroups.ts) の**両方**を変更すること。
- これはUIの出し分けのみ。APIレベルでは認証済みユーザーなら任意の `modelId` で
  推論を呼べる設計のまま（モデル切替は秘匿機能ではない、というMVPの割り切り）。
- `defineAuth({ groups })` への移行は不可（権限ゼロのグループロールが自動生成され、
  所属ユーザーのS3/推論アクセスが壊れる）。詳細は `amplify/backend.ts` のコメント参照。
