# 前処理プロファイル仕様（B方式：前処理＋モデルをセットで追加）

独自の前処理（打音検出・切り出し・ノイズ除去・特徴量化）で学習したモデルを、
**再学習せずに**このアプリへ追加するための仕組みです。
manifest の各モデルが「どの前処理（プロファイル）を使うか」を指定し、
推論Lambdaがモデルごとに前処理を切り替えます。

```
推論時:  音声(S3, 原サンプルレートWAV)
           → [manifestで指定された前処理プロファイル] → 特徴量
           → [そのモデルのONNX] → 1打ごとのkPa → 打数平均(+校正) → 結果
```

- **前処理プロファイル** = `amplify/functions/infer/preprocessors/<id>.py`（コード。追加時はPR＋再デプロイ）
- **モデル** = S3 `models/<path>/` のファイル（追加・更新は再デプロイ不要）
- 同じプロファイルを使う2個目以降のモデルは **S3だけで追加可能**

> 入力音声について: フロントはブラウザのデコードレート（通常44.1k/48kHz）の
> モノラル16bit WAVをそのままアップロードします（22050Hzへの強制変換は廃止済み）。
> 必要なサンプルレートへのリサンプルは**各プロファイルが自分で行ってください**。

---

## 1. プロファイルの実装契約

`preprocessors/<profile_id>.py` に次の2つを実装します。

```python
PROFILE_ID = "<profile_id>"   # manifest の "preprocess" に書く値と同じ

def preprocess(wav_bytes: bytes, meta: dict) -> dict:
    """
    入力:
      wav_bytes : モノラル16bit PCM WAV（サンプルレートは任意。自分でリサンプル）
      meta      : そのモデルの meta.json（前処理パラメータは自由に定義してよい）
    出力:
      {
        "features":    np.ndarray [N打, 1, H, W] float32,  # モデルへの入力。打音0個なら None
        "peakSeconds": list[float],   # 各打の時刻[秒]（UIの波形マーカー用）
        "durationSec": float,         # 解析した音声長[秒]
      }
    """
```

### 制約（PRレビューで確認します）
| 項目 | 内容 |
|---|---|
| 使用ライブラリ | **numpy / scipy のみ**（Lambdaレイヤにあるのはこれ＋onnxruntime。librosa等が必須なら要相談=レイヤ拡張） |
| 禁止事項 | ネットワークアクセス、subprocess、/tmp 以外へのファイル書込 |
| 実行時間 | 数秒以内（アプリは5秒応答が目標。`tools/measure_latency.py` で計測します） |
| 純粋性 | 入力が同じなら出力が同じ（乱数を使う場合はseed固定） |

### モデル（ONNX）側の契約
- 入力: プロファイルが出す `features` と同形 `[batch, 1, H, W]` float32
- 出力: **1打あたりの空気圧kPa**（非正規化済み） `[batch]`
- 打数平均と校正（meta.json の `calibration{x,y}`、等張回帰の折れ線）は共通コアが行う

## 2. 追加の流れ

### 新しい前処理＋モデルを追加する場合（初回）
| # | やる人 | 作業 |
|---|---|---|
| 1 | モデル作成者 | 自分の前処理を上記契約で `preprocessors/<id>.py` に移植（numpy/scipyのみ） |
| 2 | モデル作成者 | モデルをONNX化（入力=自分の特徴量、出力=1打kPa）＋ `meta.json` 生成 |
| 3 | モデル作成者 | `preprocessors/__init__.py` の `_PROFILES` に1行追加し、PR作成：<br>①プロファイル.py ②`seed/models/<モデルID>/`（model.onnx / model.onnx.data / meta.json）③`seed/models/manifest.json` 追記 |
| 4 | リポジトリ管理者 | **PRレビュー**（契約・制約・安全性）→ マージ → **再デプロイ**（`npm run sandbox:once`） |
| 5 | リポジトリ管理者 | `python tools/seed_models.py`（モデルをS3へ） |
| 6 | 誰でも | アプリをリロード→プルダウンで選択→**実測値が分かる音で精度確認** |

### 既存プロファイルを使うモデルの追加・更新（2回目以降）
手順5・6のみ（`seed/models/` にファイルを置き manifest に1行→seed実行）。**再デプロイ不要。**

### AIに作業させる場合の推奨指示（チェックポイント型）
学習repoの探索からAIに任せてよいが、**最初に特定結果を報告させ、人間が確認してから実行**させること：
「①チェックポイント ②学習時の前処理コード ③逆正規化の統計値 を選んだ根拠付きで報告し、
確認を待ってから移植を始めて。移植後は前後の特徴量一致テスト、ONNX化後はローカル検証結果を見せて」。
誤特定は“エラー”ではなく“動くが不正確”として現れるため、この確認だけは省略しないこと。

### manifest.json のエントリ
```jsonc
{
  "id": "asan-v1",            // 一意・公開後変更不可（results/labelsに記録される）
  "name": "Aさんモデル v1",    // プルダウン表示名
  "desc": "説明（任意）",
  "path": "asan-v1",          // S3 models/<path>/ の実フォルダ名と一致
  "preprocess": "asan_v1",    // 使用する前処理プロファイル（省略時 logmel_v1）
  "calibrated": false         // meta.json の校正カーブを使うか
}
```

## 3. ローカルでの動作確認（必須レベルで推奨）

numpy/scipy/onnxruntime の入ったPythonで：
```bash
python tools/smoke_local.py     # 既定プロファイルの回帰確認（参考実装）
```
自分のプロファイルも同様に `preprocess()` → `infer_from_features()` を直接呼べば
AWSなしで検証できます（`tools/smoke_local.py` がそのままサンプルです）。

### ⚠️ 移植一致テスト（前処理を書き直した場合は必須）
学習時の前処理が librosa / torchaudio 等で書かれていて numpy/scipy に書き直した場合、
**同じ音声ファイルを「学習時の前処理」と「移植したプロファイル」の両方に通し、
特徴量が一致（許容誤差内）することを必ず確認**してください。
ここがズレると、エラーは出ないのに値だけが狂う「サイレント精度劣化」になります。
AIに移植させる場合は「移植前後の特徴量一致テストを書いて実行し、結果を見せて」と
明示的に指示してください。PR説明にその結果を貼ると、レビューが通りやすくなります。

## 4. 登録済みプロファイル

### logmel_v1（既定・参考実装）
exp3_v2 系の前処理。`preprocessors/logmel_v1.py` → `audio_infer.extract_features`：
22050Hzへリサンプル → ヒルベルト包絡で打撃ピーク検出（全打）→ 各打を pre/post 秒で
切り出し・正規化 → log-mel（n_mels等は meta.json）。新しいプロファイルを書くときの
雛形としてください。

### reverb_v1（crop_mode=reverb_tail 用）
`preprocessors/reverb_v1.py`。logmel_v1 との差分はクロップのみ：
**窓 = [peak, peak + segment_samples]（pre を引かず、打撃後の残響を拾う）**。
meta.json の `crop_mode` が `reverb_tail` 以外なら ValueError（誤ペアリング防止の安全弁）。
研究repo `sagemaker/code/audio_cnn.py` build_hit_wave_samples の reverb_tail 分岐の移植で、
移植一致は `tools/verify_reverb_v1.py`（学習側コードとの特徴量突合）で検証済み。
対応モデル例: `revtail120-raw`（dk-pp-crop-revtail-20260604、holdout MAE 6.75）。

## 5. 結果JSONへの記録

推論結果（レスポンス／`results/{entity}/{id}.json`）には `preprocess`（使用プロファイルID）と
`modelId` が記録されます。再学習データの追跡にもこのペアを使ってください。

## 6. 注意（精度の責任分界）

アプリ側で保証できるのは「契約どおり動くこと」までです。
**値の正しさ＝学習時と推論時で前処理が一致していること**はプロファイル作成者の責任です。
追加後は必ず実測値が分かる音で確認してください（エラーなく動く≠正確）。
